# TrackB / SmartBus – v9 (website + backend)

A complete working website: the v8 front end, now backed by a real server with a database.
Nothing is stored in the browser any more (except the light/dark theme flag) – accounts, bookings, seats,
payments, parcels, reviews, notifications and settings all live in SQLite and are shared by every page.

## Run it (2 minutes)

```bash
pip install -r requirements.txt        # only Flask
python run.py                          # → http://localhost:8000
```

## What the backend does, page by page

| Page | Backend behaviour |
|---|---|
| **Sign up / Log in** | Real accounts, hashed passwords, secure session cookie, validation errors from the server, rate limiting, **forgot / reset password** (one-time link; shown in the response in dev, printed in the server console), `?next=` returns you to the page you came from. Social buttons answer "not configured" until you add OAuth keys. |
| **Home** | Live departures (next bus on each headline route, seats left from real bookings), newsletter sign-up (stored, de-duplicated), help chatbot answered by the server (also looks up your booking `SB…` or parcel `TB…` ID), header shows who is logged in. |
| **Services** | **Route search** (any two of 24 cities, date checks, price/duration from distance), **bus booking**, **seat reservation** (seat map from the database; double-booking is impossible – seats are unique per bus/date and re-checked at payment), **online payment** (UPI / card / saved card / net banking, Luhn + expiry checks), **coupons** (`TRACKB20`, `UPI10`, `WEEKEND30`, `STUDENT15`, `FRIEND100` – rules enforced by the server), **cancel booking** with a tiered refund (24h+ 100%, 6–24h 75%, 2–6h 50%, under 2h none – edit `REFUND_TIERS` in `backend/config.py`). |
| **History** | Your trips from the database: filter/search/sort, details, rate a completed trip, cancel (seats are released, refund recorded), remove / restore, downloadable receipt generated by the server, "Track bus" for the exact booking. |
| **Live tracking** | `GET /api/tracking` returns the stops, schedule, driver and the bus position. Source order: **real GPS** (if a device posts to `/api/tracking/gps`) → **timetable** for your booked trip → an always-running **demo bus** (8× time-lapse, switch off with `TRACKB_DEMO_FLEET=0`). Bus reviews (write, filter, "helpful"), driver call + chat log, help tickets (delay / lost item / support / emergency) and a share link that never contains your booking ID. |
| **Parcel & luggage delivery** | Server-side pricing (weight, distance, insurance, pickup/delivery, 5% GST), bus selection with 60-minute hand-over cut-off, payment, consignment ID + delivery OTP, public tracking by ID (private details hidden from non-owners), my shipments, cancel before loading, receipt. Stages advance in minutes for the demo (`TRACKB_PARCEL_DEMO_MINUTES=0` ties them to the real bus times). |
| **Profile** | Edit profile (field-level server validation), **payment methods** (only brand, last 4 digits and expiry are stored – never the full number or CVV), **saved routes** (add / edit / alerts / delete; "Book" opens Services pre-filled), **notifications** (real, created by bookings, cancellations, parcels; mark read/unread; the bell on every page shows the live count), notification preferences, **settings** (theme and language synced to your account, privacy switches, blocked users, change password, delete account). |
| **Developers** | Team list from the server; the **admin** account can upload photos (validated, stored on disk). |
| **Contact / Careers** | Messages saved with a reference number and visible in the admin panel. |
| **Admin** `/admin/` | Stats, contact inbox, help tickets, bookings, parcels (change stage), newsletter list + CSV export, GPS feed instructions. |

## Project layout

```
run.py                  start the server
backend/                Flask app (config, db schema + demo data, one module per area)
  auth.py bookings.py tracking.py parcels.py account.py support.py admin.py
  catalog.py            cities, distances, bus schedules, seat inventory, coupon rules
  payments.py           payment validation + (simulated) gateway
shared/api.js           browser client used by every page (API calls, login state, bell, theme sync)
index.html, services/, history/, tracking/, delivery/, profile/, developers/, trackb-signup/, pages/, admin/   the website
instance/               created on first run: trackb.db (database), uploads/, secret.key   (private, git-ignored)
tests/test_api.py       end-to-end API tests
docs/FRONTEND-CHANGELOG.md   notes from the v1–v8 front-end work
```

Only the website folders are served; `backend/`, `instance/`, `.env` and `*.py` are never reachable over HTTP.

## Feeding real GPS data

```bash
curl -X POST http://localhost:8000/api/tracking/gps \
  -H "X-GPS-Key: <TRACKB_GPS_KEY>" -H "Content-Type: application/json" \
  -d '{"bus":"hrtc-volvo-1830","lat":30.7333,"lng":76.7794,"speed":58}'
```
While a bus has a fix newer than 3 minutes, the tracking page shows that position instead of the schedule.
Bus codes are listed by `GET /api/search` (`code`).

## Before you go live (honest list)

1. **Payments are simulated.** `backend/payments.py` validates everything and records the payment but never charges anyone.
   Replace `_gateway_charge()` with Razorpay / Cashfree / Stripe. Test rule: a card ending `0002` is declined.
   Valid test card: `4242 4242 4242 4242`, any future expiry, any 3-digit CVV.
2. **Bus timetable and operators are generated** from distance (`backend/catalog.py`). Replace `buses_for()` with your real operator inventory.
3. **E-mail / SMS** are not sent. Hook `forgot()` in `backend/auth.py` (reset link) and the notification helper to your provider.
4. **Social login** needs OAuth credentials.
5. Set `TRACKB_ENV=production`, a long `TRACKB_SECRET_KEY`, change the admin and GPS keys, serve behind HTTPS
   (e.g. `gunicorn run:app`), and back up `instance/trackb.db`.
6. Rate limiting is in-memory (per process); use Redis if you run several workers.
7. Map tiles, routing (OSRM) and fonts still load from the internet, as before.
